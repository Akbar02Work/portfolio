# Производительность: методика и сохранённые решения

Актуальные команды сверены 03.10.2026. Числа ниже — сокращённый исторический
снимок оптимизации **05.09.2026**, а не показатели нынешнего production-релиза.
Сырые артефакты измерений игнорируются Git и могут отсутствовать в новом checkout.

## Повторить измерения

Нужны production-сборка и установленный Chromium версии локального Playwright.
После изменения Creative сначала обновить embed по [README](../../README.md#build-and-embed).
Запускать из корня **последовательно**, без параллельных E2E:

```bash
npm run build
node scripts/profile-performance.mjs after
node scripts/profile-interactions.mjs after
PERF_FLOW=projects node scripts/profile-navigation.mjs after
```

Для сравнения повторить с меткой `before` на исходной сборке. Скрипты самостоятельно
запускают ограниченный static server с gzip; это не эмуляция Vercel/CDN/TLS.

| Скрипт | Что измеряет | Порт |
| --- | --- | --- |
| `profile-performance.mjs` | Холодную загрузку шести сценариев, LCP/FCP/CLS, long tasks | 4180 |
| `profile-interactions.mjs` | CPU-профили и вызовы DOM/WebGL при старте, простое, скролле и pointer input | 4181 |
| `profile-navigation.mjs` с `PERF_FLOW=projects` | Открытие AI Voice Notes и возврат к списку, включая шторку | 4182 |

**Ограничение navigation:** обычный режим Business ↔ Creative ожидает сразу доступную
ссылку Creative. Теперь она находится в диалоге выбора версий: его нужно открыть
тремя кликами по логотипу, затем выбрать Creative. Скрипт ещё не учитывает этот шаг;
в этой документации старый сценарий не предлагается к запуску.

Результаты: `logs/performance/<label>/`. Управление запуском:

- `PERF_OUTPUT_DIR` — другой каталог отчётов.
- `PERF_RUNS` — число прогонов load/navigation; по умолчанию 3.
- `PERF_SCENARIOS` — имена load-сценариев через запятую, из массива в скрипте.
- `PERF_ROUTES` — URL для interaction-профиля через запятую.
- `PERF_PORT` — порт только load-профайлера.
- `PORTFOLIO_DIST_DIR`, `PORTFOLIO_CONFIG` — сохранённые build/config для сравнения.
- `PERF_DISABLE_WEBGL=true` — диагностический load-прогон без WebGL, не production-настройка.

## Как читать результаты

Load/navigation: CPU ×4, задержка 150 мс, загрузка 200 000 байт/с, gzip.
Load отключает кеш и создаёт новый контекст для каждого прогона; navigation оставляет
кеш включённым. Interaction использует CPU ×4 и сеть без ограничения.
Viewport: 1440×1000/DPR 1 и 390×844/DPR 2 для load; interaction/navigation — desktop.

- `ready` означает первый кадр с `h1` после снятия `body.is-loading`, не TTI и не
  завершение intro. Load собирает метрики до `ready + 2,5 с`.
- «Блокировка» — сумма `max(0, longTask.duration − 50 мс)` в этом окне, не INP
  и не Lighthouse TBT.
- Ресурсы в старой таблице — сжатые тела ресурсов, без HTML и HTTP-заголовков.
- Использовать медианы одинаковых сценариев и фиксировать версии Node/браузера,
  настройки сборки, наличие Sentry DSN и сохранённый source/build snapshot.
- Headless software WebGL не доказывает аппаратный FPS или расход батареи.
  Лабораторные результаты не заменяют реальные устройства, RUM и проверку CDN.

## Снимок 05.09.2026

Сборки: Node 24.20.0/Vite 8.1.5. Профили: Node 26.0.0, Chromium 149.0.7827.55,
macOS/Apple M4; три последовательных прогона с указанным выше throttling.
Все времена ниже — медианы в миллисекундах.

| Business mobile | 2112 → 1696 | 1547 → 1683 | 61 → 42 |

определённые ready и блокировка.* CLS был 0 вне desktop Creative, около 0,005 в нём.

## Что сохранить при будущих правках

- **Route preload:** портрет использует общие с React `srcset/sizes`; кейс загружает
  существующий cover, не все слайды. Responsive preload без `href` избегает лишнего
  полного портрета в проверенном WebKit. Ранние изображения устанавливаются после
  присоединения `picture`; сохранять порядок атрибутов и image fallback.
- **Phone frame:** вариант 512 px WebP уменьшил рамку 37,4 → 10,5 KiB. Исходный PNG
  остаётся fallback; выбор размера должен учитывать плотность пикселей.
- **Creative scroll:** общий ref вместо наследуемого `--scroll` и немедленного чтения
  computed style. В старом стенде RecalcStyle за 4 с скролла: 618 → 115 мс.
- **Локальные обновления:** часы/мигающий символ изолированы; прелоадер обновляет ref
  и transform. Таймеры не должны перерисовывать всю PortfolioPage.
- **WebGL:** запуск после готовности страницы; trail-pass пропускается до первого
  pointer input; attribute locations кешируются. Качество/DPR не снижались.
- **Кеш:** unversioned media/fonts — сутки, hashed JS/CSS — год immutable. Старый
  повторный Creative → Business передавал 165,9 → 0,9 KiB ресурсов, без учёта HTML.
  Срочная замена media требует нового имени файла.
- **Sentry:** отдельный динамический chunk активируется при production DSN;
  включённый мониторинг меняет профиль загрузки и должен учитываться в сравнении.

Не переносить старые проценты ускорения или результаты CI на текущий релиз.
Проверки поведения изображений и WebGL находятся в `tests/e2e/performance-contracts.spec.ts`;
актуальные бюджеты и команды — в README. Исходная версия отчёта сохранена в Git.
